# 决策备忘：对倒后违约（pooled C 稀释）怎么处理

**日期** 2026-10-24 · **状态** 已按建议采纳方案 A 为本仓库的推荐规则集（`Rules::recommended()`），全套验证通过；创始人如要改选 0 或 B，改一个开关重跑 `verify.py` 即可 · **数据** `out/dilution_variants.csv`、`out/fee_wash.csv`、`out/chaos.csv`、notebook 02

## 问题

一个池子只有一种 C，所有 C 平分池内资产。攻击者在一批里以 K−1 自买自卖 W 个资产，到期不还款；他的 C 把币原路领回，R 什么都不付。因为违约单位按比例分走诚实借款人还的 K，价值从诚实出资人流向攻击者。成本：v0.7 为 0，v0.8 为 0.06% 名义额（两边成交费）。

100 ETH 诚实成交 @3300、K = 3400、对倒 100 ETH：

| | 攻击者盈亏 | 诚实出资人盈亏 |
|---|---|---|
| v0.7 | +4,750 USDC | −5,250 USDC（本金的 1.6%） |
| v0.8（现决定） | +5,019 USDC | −4,923 USDC |

v0.8 的 5% 利差分成和 0.03% 成交费对此无效：攻击者的成交价在 K−1，利差几乎为零。

## 三个选项，都已在模型里跑完全套

| 选项 | 机制 | 攻击者盈亏（1× 对倒） | 诚实出资人 | 诚实流程的影响 | 代价 |
|---|---|---|---|---|---|
| **0. 保持共享池** | 现状 | +5,019 | −4,923 | 无 | 攻击持续可行；带宽、保护价都挡不住 |
| **A. C/R 按清算批次分 tranche**（`Rules::v08_tranche()`） | 每批成交的 C/R 各成一个 tranche；还款、出价、费用托管按 tranche 结算；认领只拿本 tranche 的 quote 和币 | **−102** | **−50**（只剩手续费） | 基线 8 组种子：违约率相同，国库收入差 < 1.5%，出资人回报差 < 0.01 pp；混沌 6 种子 0 违规，tranche 账本每步一致 | C 不再跨批次同质：ERC-6909 id 要带批次号，PositionMarket、ERC-20 包装、Kuru 挂牌要按批次列；金库不受影响（金库对外是自己的份额） |
| **B. 竞争清算也受带宽约束** | P* 偏离上次成交价超过（放宽后的）带宽的批次不成交 | 1.5% 带宽：0（被挡）；8% 带宽：+5,019 | 1.5%：−50；8%：−4,923 | 熔断逻辑复用现有的 1.5× 放宽和 3 批重置 | 只对锚定类（1.5%）有效；主流 8% 带宽下 K−1 离市价 3% 仍在带内；真实大波动时会连续流拍 |

## 建议

选 **A**。理由：

1. 它是唯一把攻击收益打到负数的方案，且不依赖带宽参数。
2. 诚实流程的数字与 v0.8 几乎一致，混沌测试全过，模型已把 repay / bid / closeWindow / claim 的 tranche 版本写出来，合约改动面清楚：`PoolState` 加 tranche 表，C/R id 加批次号，`claim` 按 tranche 循环。
3. 代价集中在二级市场的展示层。可以先按 tranche 实现核心，Kuru / PositionMarket 侧"同一池子同一到期"的 tranche 价格天然接近，列表按批次聚合即可。

如果选 **0**（保持），需要接受：每个诚实出资人暴露于"同池后批次的违约"，攻击成本为 0.06% 名义额；应在前端和文档里明说。

如果选 **B**，只对锚定类资产有意义，主流资产要再想别的。
